# ВЕРШИНА (Vertex)

**Восстановление финансовой структуры организованной группы по транзакционной сети.**
Кейс «Граф денег» · HackAlem AI · заказчик Freedom · команда Bond.

> AML-аналитик видит только низ цепочки — дропов. «Вершина» разворачивает граф на 4 колена вверх,
> присваивает каждому участнику **роль по формальному правилу с порогом**, группирует сеть в кластеры,
> выдаёт **ранжированный список «кого проверять первым»**, заводит **кейсы** для разбора и рисует
> **интерактивный граф** с направлением потоков. На каждый узел — числовое обоснование.

## Принцип: объяснимость, без чёрных ящиков

Каждая роль — **правило с порогом**. Перцентильные пороги вычисляются из данных при каждом запуске;
структурные константы (`in_deg ≥ 3`, `pass_through ∈ [0.7, 1.3]`, `≥ 0.5`) заданы явно. Всё
детерминировано (`seed=42`, фикс. инициализация HITS), локально, без облака/GPU/платных сервисов,
воспроизводимо (< 5 минут; факт ~3 сек).

### Метрики

- **PageRank** (взвешен по `sum_kzt`) — влиятельность узла в потоке денег.
- **HITS, взвешенный по деньгам** (своя power-iteration — в networkx весов нет): `authority` = денежный
  сборщик (к нему стекаются крупные суммы), `hub` = денежный распределитель.
- **Betweenness, взвешенный**: расстояние ребра = `1/sum_kzt` → крупные потоки «короче», посредничество
  считается по деньгам. Это выбранная аналитическая модель, а не восстановление фактического маршрута денег.
- **Louvain** — сообщества на неориентированной взвешенной проекции (направление там теряется — оговорено).
- **Простые циклы (≤5)** — возвратные потоки (layering); хранятся и узлы, и рёбра циклов.
- **Временной лаг** — медиана между отправкой и ближайшим предшествующим получением (бинарный поиск).

### Словарь ролей и правила (порядок = precedence, первое подходящее выигрывает)

| # | Роль | Правило | Кол-во |
|---|---|---|---:|
| 1 | **terminal** (обрезка) | `depth = 4 & out_deg = 0` → слепая зона, `role_score = 0.35`, помечено «ОБРЕЗАН» | *(входит в 1535)* |
| 2 | **terminal** | `out_deg = 0 & in_deg ≥ 1` → деньги осели (гипотеза) | 1535 |
| 3 | **coordinator** | `betweenness ≥ p98` **и** `pagerank ≥ p90` **и** есть вход и выход (узел-мост) | 12 |
| 4 | **distributor** | `out_deg ≥ p95(≈16.35)` **или** (`out_deg ≥ 5` и `out_kzt ≥ p90`), при `out_deg ≥ in_deg` | 99 |
| 5 | **consolidator** | `in_deg ≥ 3` и `in_deg ≥ out_deg` | 85 |
| 6 | **transit** | не-seed, есть вход/выход, `0.7 ≤ pass_through ≤ 1.3` | 310 |
| 7 | **transit** (резерв) | не-seed, двусторонний поток, `pass_through ≥ 0.5` | *(входит в 310)* |
| 8 | **peripheral** | остальное (изолированные, слабые, seed без роли) | 207 |

Сток и слепая зона проверяются **раньше** ролей с исходящими, чтобы `out_deg = 0` не попал в сборщика.

### Приоритет проверки (0–1)

```
raw = 0.30·вес_роли + 0.20·rank(pagerank) + 0.20·rank(betweenness)
    + 0.15·rank(in_kzt+out_kzt) + 0.08·min(n_seed_in,3)/3 + 0.07·in_cycle
```
Затем min-max в 0–1; при равенстве — по gid. Вес роли: coordinator 1.0 → consolidator 0.85 →
distributor 0.75 → transit 0.55 → terminal 0.40 → peripheral 0.10.
`role_score` — поддержка эвристики, **не** вероятность виновности.

## Четыре ловушки кейса — как обработаны

1. **`out_deg = 0` ≠ «деньги осели».** 444 узла на 4-м колене — обрыв обхода. Все помечены
   `truncated_by_depth`, роль `terminal` с `role_score = 0.35` и пометкой «ОБРЕЗАН — исход не наблюдаем».
2. **У seed занижен вход.** Граф собран *от* seed по исходящим. Для seed `pass_through = -1` (неприменимо),
   роль по нему не присваивается (**0 seed в transit**), сырая входящая сумма в evidence не показывается
   (исходящая показывается — она наблюдаема).
3. **Сумма ≠ количество.** В evidence и суммы, и количество переводов; распределитель учитывает `out_deg` и `out_kzt`.
4. **Граф направленный и взвешенный.** Все центральности — на ориентированном взвешенном графе.
   Кластеризация Louvain — на неориентированной проекции (оговорено явно).

**Неизвестные значения не заменяются нулём:** `pass_through = -1` (нет входа/seed), `turnover_days = -1`
(нет наблюдаемой пары получения-отправки).

## Схема выгрузок (контракт для жюри)

**nodes_roles.csv** — 2 248 строк, 24 колонки:
`gid, role, role_score, cluster_id, priority_score, evidence, in_deg, out_deg, in_kzt, out_kzt,`
`pagerank, pass_through, depth, is_seed, truncated_by_depth, hub, authority, betweenness, net_kzt,`
`n_seed_in, in_cycle, turnover_days, in_tx, out_tx`.
Типы: `gid/*_deg/*_tx/depth/n_seed_in/cluster_id` — int; `*_kzt/*_score/pagerank/pass_through/hub/`
`authority/betweenness/net_kzt/turnover_days` — float; `is_seed/truncated_by_depth/in_cycle` — bool;
`role/evidence` — text. `evidence` ≤ 200 символов, всегда с числами.

**clusters.csv**: `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis`.
**top_nodes.csv**: `rank, gid, role, priority_score, why` (30 строк).

Все файлы — UTF-8. `gid > 2^53` в JSON сериализуются строками (JS Number теряет точность).
Пайплайн включает **валидатор** (`validate_outputs`): падает при нарушении схемы/диапазонов/полноты.

## Дашборд `out/vertex.html` — 4 вкладки

- **Граф** — направленный граф: цвет = роль, размер = приоритет, стрелка = направление, кольцо = seed,
  пунктир = слепая зона. Фильтры по ролям/приоритету/кластеру, поиск по gid, фокус на топ-30,
  **подсветка циклов (layering)** красным. Клик по узлу → карточка с обоснованием и контрагентами.
- **Кейсы** — авто-созданные кейсы по подозрительным кластерам с «логами» (переводами). Рабочий процесс
  аналитика: *взять в работу → закрыть* (Эскалация в ПО / Ложное срабатывание / Мониторинг) + заметки.
  Статусы сохраняются в браузере (localStorage).
- **Устойчивость** — что будет с сетью при изъятии топ-N узлов (метрики слабой связности + график);
  «показать на графе» удаляет топ-N в графе.
- **Ассистент** — локальный помощник по правилам (офлайн): вопрос о ролях/gid/кластере/циклах →
  ответ по графу с кнопками перехода к узлам.

## Масштабирование (~1 млн узлов)

Текущая реализация точна и укладывается в секунды на 2 248 узлах. При росте до ~1 млн:
- Точный `betweenness` (O(V·E)) заменить на аппроксимацию по сэмплу источников (`k`-sampling).
- Перечисление коротких циклов ограничить/сэмплировать; хранить только рёбра циклов.
- Louvain → Leiden на `igraph`; хранить граф в CSR/`igraph`, а не в `networkx`.
- Ингест — колоночно (PyArrow/Polars), инкрементальные батчи вместо полного пересчёта.
- Дашборд — рендерить подграф топ-N + окружение, остальное по запросу (серверная пагинация).

## Ограничения (честно)

Нет ground truth — оценка по обоснованности критериев, не по accuracy. Терминалы 4-го колена
принципиально неразличимы без данных за пределами выборки (помечаем, не угадываем). Время — дневной
гранулярности. Циклы по месячным агрегатам не доказывают возврат той же суммы. Betweenness зависит от
выбранной модели расстояния. Выводы — гипотезы для проверки, не утверждения о виновности.
