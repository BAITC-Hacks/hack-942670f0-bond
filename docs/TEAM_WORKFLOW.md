# Работа вдвоём
Проверенная среда — Python 3.12. У каждого своя .venv, одинаковый requirements.txt.
Не переносите .venv между компьютерами и не коммитьте ключи.

## Получить интеграцию
Сначала сохраните собственные изменения отдельным коммитом в своей ветке.
Затем:
```bash
git fetch origin
git switch --track origin/team/vertex-integration
```
Если ветка уже существует: git switch team/vertex-integration, затем git pull --ff-only.
После слияния PR оба переходят на main и выполняют git pull --ff-only.

Windows: .\\run.ps1
Linux/macOS: bash run.sh
Проверка: Python из .venv запускает verify.py.
Открыть out/vertex.html; для локального сервера — python run.py --serve --skip-build.
Не запускайте два сервера на одном порту. После пересборки перезапустите сервер.

## Обмен кейсами
Во вкладке «Кейсы» экспортируйте JSON заметок и передайте файл напарнику.
Он импортирует файл на той же версии анализа. Чужая версия отклоняется.
Конфликты по умолчанию сохраняют локальную заметку; замена только с явной галочкой.
Это обмен файлами, не общая база и не одновременное редактирование.
localStorage относится к конкретному браузеру и адресу; перед сменой порта или очисткой браузера экспортируйте заметки.
Старые vertex_cases_v2 не переносятся автоматически: прежние порядковые номера могли обозначать другие сообщества.

## Изменять проект
Для каждой задачи — отдельная ветка от актуального main, коммит, push, PR.
Перед PR: verify.py; при изменении интерфейса — проверка в браузере.
Не используйте force push в main. Изменение правил согласуйте вместе: оно меняет ранжирование и версию анализа.
OpenAI необязателен; ключ каждый задаёт локально, без отправки в Git или напарнику.
